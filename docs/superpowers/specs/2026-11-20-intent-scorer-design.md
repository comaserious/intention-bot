# 사용자 발화 의도 점수 래퍼 설계

작성일: 2026-11-20 / 상태: 승인 대기

## 1. 목적과 배경

경상북도 "주민케어 AI 서비스" 제안(RFP) 대응 시스템에서, 사용자 발화가 어떤 서비스를 원하는지 **정의 기반으로 점수화**하는 래퍼를 만든다. RFP SFR-008은 질의의 의도·주제를 분석해 정착지원, 생활지원, 소상공인 지원, 공장설립 서비스로 연계하고, 복합 질의는 관련 서비스를 함께 제공하며, 모호한 질의는 추가 정보를 요청하고 응답 불가 질의는 담당기관을 안내하라고 요구한다.

의도 정의를 넣으면 발화마다 `{의도: 점수}`를 돌려주는 zero-shot 방식이다. 학습 데이터 없이 정의만으로 동작한다.

## 2. 목표 / 비목표 / 반(反)목표

**목표**
- 의도 4개(정착지원, 생활지원, 소상공인지원, 공장설립지원)와 "해당없음"에 대한 점수 반환
- 의도 정의는 코드 밖(설정 파일)에서 수정 가능
- 복합 질의와 해당없음을 점수로 판단할 수 있을 것
- 정확도와 소요 시간을 재현 가능하게 평가하는 스크립트 제공

**비목표**
- AI 민원실(서류 작성·접수)은 의도에서 제외 (사용자 결정)
- 점수 기반 분기 처리(추가 질문, 담당기관 안내)는 이 래퍼 범위 밖. 점수만 반환
- RAG, 답변 생성, 모델 파인튜닝

**반목표 (기술적으로 동작해도 실패인 경우)**
- 로컬 모델 서버에 과도한 병렬 부하를 거는 구조
- 잘 맞는 것처럼 보이지만 해당없음을 못 걸러서 무관한 질문이 서비스로 연결되는 구조

## 3. 제약

- 모델: 사내 vLLM 서버의 `google/gemma-4-26B-A4B-it`, OpenAI 호환 API (`.env`의 `BASE_URL`). 임베딩 엔드포인트 없음, logprobs 지원
- **로컬 모델이므로 병렬 요청 수를 제한한다.** 요청 폭주 시 서버 부담이 크다
- 환경: conda `intention-bot` (Python 3.14.10), `openai` 패키지
- 엔드포인트 주소와 API 키는 코드에 하드코딩하지 않고 환경변수/설정으로 받는다

## 4. 접근 방식

| 방식 | 내용 | 스파이크 결과(24개 발화) |
|---|---|---|
| A1 | 의도를 A/B/C… 라벨로 제시, 첫 토큰 logprob을 softmax. 순서 1번 | 1위 정답 15/16, 집합 일치 17/24, 평균 0.06초 |
| **A4 (채택)** | A1을 의도 순서를 돌려 4번 호출하고 평균 (순서 편향 제거) | 1위 정답 **16/16**, 집합 일치 **23/24**, 평균 0.29초 / 최대 0.72초 |
| B | 의도별 yes/no logprob | 8/16, 10/24. 무관한 의도에 높은 점수 |
| B2 | B에 전체 정의를 보여주고 yes/no | 16/16, 19/24, 평균 0.09초. 해당없음 판정 우수, 복합 질의 약함 |

선택: **A4**. 이유: 정확도가 가장 높고, 복합 질의에서 두 의도에 점수가 나뉘며, "해당없음" 선택지를 넣어 무관 질의를 거른다. B2는 부하(호출 수) 때문에 이번에는 제외하고 향후 개선으로 남긴다(7절).

스파이크 수치는 표본이 작고(24개), 일부 발화는 임시 작성, 기준값 미튜닝이라 **방향성 참고용**이다.

## 5. 설계 (확정된 것)

**점수 계산**
- 프롬프트: 의도 N개 + "해당없음"을 알파벳 라벨 옵션으로 제시, 발화 제시, "알파벳 한 글자만" 답하도록 지시
- 호출: `temperature=0`, `max_tokens=1`, `logprobs=True`, `top_logprobs=20`
- 점수: 라벨 토큰들의 확률(exp(logprob))을 합 1로 정규화. 후보에 없는 라벨은 0 처리
- 순서 회전: 의도 N개를 N가지 순환 순서로 나열해 N번 호출하고 점수를 라벨이 아닌 **의도 이름 기준으로 평균**
- 반환: `{"정착지원":…, "생활지원":…, "소상공인지원":…, "공장설립지원":…, "해당없음":…}` (합 1)

**의도 정의 (RFP 기반 초안, 설정 파일로 관리)**
- 정착지원: 경북 이주·전입자의 정착 지원. 정주여건 비교·지역 추천, 전입 인센티브·정착지원금·월세 지원, 전입 정책과 신청 절차
- 생활지원: 도민 일상 생활 안정을 위한 복지·돌봄·주거. 기초연금, 노인복지·노인맞춤돌봄, 아이돌봄, 주거복지의 안내·자격 확인·서류
- 소상공인지원: 소상공인·예비창업자 지원. 창업 방법, 정책자금(금리·이차보전), 청년 창업 지원, 지원사업 추천과 신청 준비
- 공장설립지원: 공장 설립 준비 기업. 설립 조건, 입지 규제·용도지역, 계획입지/개별입지, 배출시설 등 인허가, 공장설립 AI 사전진단

**복합 질의 / 해당없음 판단 (호출 측이 쓸 수 있게 헬퍼 제공)**
- "해당없음"이 1위면 해당 의도 없음
- 그 외에는 점수가 기준값 이상인 의도를 모두 반환 (초기 기준값 0.2, 스파이크에서 임시 사용. 튜닝 필요)

**부하 제어**
- 요청당 호출 수는 `rotations` 설정으로 1~N 조절 (기본 N=의도 수). A1(1회)로 줄이면 속도는 4배 빠르지만 정확도가 떨어진다
- 동시 요청 수를 제한하는 세마포어(설정값)를 둔다. 기본값은 구현자가 서버 상황을 보고 정한다

**평가 (필수 포함)**
- 정확도: 1위가 정답인 비율, 복수 의도 집합 일치 비율, 해당없음 판정 정확도
- **소요 시간**: 평균, 중앙값, p95, 최대 (요청당 end-to-end, 워밍업 호출 제외)
- 평가 데이터: 사용자가 제공한 16개 발화(의도별 4개) + 추가 테스트(복합 4, 모호/무관 4). 실제 사용 발화가 모이면 교체·추가
- 방식별 비교표를 동일 형식으로 출력 (A1/A4 비교 가능하도록)

## 7. 향후 개선 (이번 범위 아님)

- **B2 보조 도입**: 의도별 yes/no(전체 정의 제시)로 "해당없음" 판정과 확신도를 보강. 스파이크에서 속도(평균 0.09초)와 해당없음 판정은 좋았으나 복합 질의가 약했다. 호출이 4번 추가되므로 서버 부하를 확인한 뒤 도입
- 기준값(복합 질의, 해당없음) 튜닝과 보정(calibration)
- 실제 발화 기반 평가셋 확충, 정착지원/생활지원 경계 사례 정리
- 의도 정의에 예시 발화 추가(few-shot) 효과 검증
- 점수 기반 분기 처리(추가 질문 요청, 담당기관 안내)와의 연동
